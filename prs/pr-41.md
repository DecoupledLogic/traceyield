## Summary

Adds `traceyield run`, which writes one JSON document for a single delivery run: a Claude Code session's main thread, the subagents it spawned and, with `--cwd`, the Codex sessions that started in that directory inside the window. The document lists each agent's models and reasoning efforts, every model request with its tokens and estimated cost, every tool call with its duration, input and output, and the failed or refused calls grouped by `classification.ERROR_META`.

The report cannot answer this today. `usage.db` keeps only lengths and hashes of text in its default capture, has no column for reasoning effort, and does not separate a subagent from its parent session.

Approach (Decision 0010):

- `src/traceyield/runs.py` reads each lane through its provider's `parse_file()`. It imports neither `canonical`, `report` nor `sqlite3`, and `tests/test_runs.py::TestStoreUntouched` asserts that.
- Lane discovery is a `run_lanes()` method on each provider. Claude takes a session id and returns every `<project>/<session>.jsonl` plus `subagents/agent-*.jsonl`. Codex takes a directory and a window and returns rollouts whose `session_meta.cwd` is that directory or below it.
- Records that repeat one request's usage merge into one turn, keyed on `requestId`, then `message.id`, then the record `uuid`. `ClaudeProvider` still yields one `Turn` per record; changing that is Decision 0011.
- A request belongs to the window when its first record does, and its tool calls follow it.
- Four fields are added to the neutral records with no column in the store: `Turn.effort`, `Turn.message_id`, `Segment.ts`, `Segment.origin`. `canonical.write()` names its columns, so it ignores them.

Alternative not taken: persisting per-call text and effort in `usage.db`. That stores prompt and tool text for every user by default to serve a need that arises per run.

Effects to review:

- **Schema:** none. No table or column changes.
- **Store contents:** unchanged. `CodexProvider` gains `custom_tool_calls=False`. Only `runs.default_providers()` sets it, so the scheduled ingest still stores Codex `custom_tool_call` events as `raw_event` rows. `test_the_scheduled_ingest_still_leaves_freeform_calls_as_raw_events` covers this. The report therefore still does not count those Codex tool calls.
- **Privacy:** the document contains prompt, reply and tool text. It is written only by this explicit command, to stdout or `--out`. Each field is redacted and then cut to `--clip` characters. Redaction is a pattern match on credential-looking names, URL passwords and a few token shapes; it misses a secret under any other name. `--no-text` removes every field derived from transcript text, including call summaries and subagent descriptions.
- **Pricing:** costs use the existing `pricing.cost_of()` and rate cards unchanged. A model with no rate card is counted in tokens and marked not priced. Decision 0012 covers the rate cards themselves.
- **Performance:** Codex discovery globs the Codex root and opens the first line of each rollout, skipping dated folders more than a day outside the window.
- **Compatibility:** `traceyield`, `traceyield report` and `--machine-dir` behave as before. `run` is dispatched before the existing parser.

Two pre-PR reviews ran on this branch (Codex, and the in-house code review). Their 19 findings are fixed in commits `9688b9f` and `5fd22db`. Three review notes are not addressed here: `parse_file()` still stamps Codex calls with the turn already seen and `runs.py` re-attributes them by time; the two `run_lanes()` methods have different signatures; and `extract()` names the `claude` and `codex` providers directly.

No real transcript, session id or credential is in the diff. Fixtures are synthetic.
