## Summary

`ci` fails on `main` (run 45640207914, commit 20e49af) and on PR #41 with one test, `test_equivalence_session_project_first_wins_across_files`: `'projB' != 'projA'`. The commit before it on `main` passed 20 minutes earlier, and the only file that differs is `prs/pr-41.md`.

`aggregation.analyze()` and `canonical.ingest()` list transcript files with `glob.glob(..., recursive=True)` and do not sort the result. For a session with turns in two project folders, the session's project, cwd and branch are taken from the first file processed, so they depend on the order the filesystem returns directories. Linux does not define that order.

This change sorts the listing in both walkers. "First" now means first in path order on every platform, which is the order Windows already produced. It does not change the rule to "earliest timestamp".

Effects to review:

- **Reported numbers:** on a machine whose filesystem already listed folders alphabetically, nothing changes. On one that did not, a session spanning two project folders can move to the other project in `sessions[...]["project"]`. Per-turn `by_project` cost is unaffected because it uses each turn's own file.
- **Schema, privacy, pricing:** none.
- **Not changed:** `health.scan_claude()` and `health.scan_codex()` also glob unsorted. No acceptance criterion covers them.
